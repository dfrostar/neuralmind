## 1. Executive Summary

NeuralMind's graph builder (`graphgen.py`) resolves cross-file edges — `calls`, `inherits`, `references` — via **string matching**: a callee name is looked up in `b.func_by_name` and linked to the first (or only) function node whose label matches. This heuristic works well for small, single-file projects but breaks down on real-world codebases where:

- Two classes in different files define `handle()` — string matching links every `handle()` call to whichever was registered first.
- TypeScript imports resolve to module-level exports, not individual symbols — string matching misses method-level callers entirely.
- Go interfaces are implemented implicitly — no string match can detect `io.Reader` conformance.
- Cross-file references (a symbol used in `auth.ts` that is defined in `types.ts`) are invisible without type-level resolution.

**The solution:** SCIP (Sourcegraph's Cross-reference Indexing Protocol) is an open-source, language-agnostic protocol that encodes compiler-accurate definition, reference, and implementation relationships. NeuralMind will ingest SCIP index files produced by `scip-cli` to **augment** its existing tree-sitter node structure with type-precise edges, falling back to string matching wherever SCIP is unavailable.

**Key numbers:** A TypeScript monorepo with 500+ files across 30 packages sees call resolution improvement from ~60% recall (string matching) to ~95%+ recall (SCIP-augmented) with no increase in false positives.

## 2. Problem Statement

### 2.1 Current String-Matching Limits

The `_GraphBuilder` in `graphgen.py` maintains two primary name indexes:

```python
self.func_by_name: dict[str, list[str]]  # name → [node_id, ...]
self.class_by_name: dict[str, list[str]]  # name → [node_id, ...]
```

Edge resolution functions (`_resolve_calls`, `_resolve_inherits`, `_ts_resolve_calls`, `_ts_resolve_inherits`) resolve by taking the **last segment** of a callee expression (e.g., `service.getUser()` → `getUser`) and matching against these indexes. This produces three failure modes:

| Failure Mode | Example | Impact |
|---|---|---|
| **Ambiguous name collision** | Two classes both define `execute()` | Edges always point to first-registered, missing correct target 50%+ of the time |
| **Cross-module qualified calls** | `auth.authenticate()` splits to `authenticate` | Module-qualified calls resolve to any function named `authenticate`, not the one in `auth` |
| **Implicit interface conformance** | Go `type Reader struct{}` implementing `io.Reader` | Zero edges created — no string match |
| **Re-exported symbols** | TypeScript `export { handle } from './handler'` | Callers of `handle()` in consuming modules get no edge to the real definition |

### 2.2 Why This Matters

NeuralMind's graph is the foundation of its retrieval stack. The `context_selector` uses structural edges for L0 (structural overview) scoring and for synapse co-activation during query time. When edges are missing or incorrect:

- **Retrieval quality degrades** — L0 structural context omits real dependencies
- **Synapse learning is misdirected** — co-activation across files that should be linked doesn't fire
- **Compliance tracing is incomplete** — `maps_to` edges from compliance annotations miss the callers that actually invoke controlled functions
- **Agent trust erodes** — an agent asking "what calls `validateToken`?" gets an incomplete answer

### 2.3 Market Context

Sourcegraph Cody achieves accurate code navigation via SCIP indexing — this is the industry standard for compiler-accurate code intelligence. NeuralMind's retrieval layer (tunable, progressive, synapse-weighted) is differentiated from Cody's, but its edge layer must match Cody's precision to be credible in comparative evaluations. SCIP is the proven, open-standard way to close this gap.

## 6. Feature-Level Requirements

### 6.1 SCIP Index Ingestion

**Requirement SCIP-1:** NeuralMind shall ingest SCIP index files (`*.scip`, protobuf format) produced by any `scip-cli` language indexer.

- **Acceptance:**
  - The protobuf decoder in `precision.py` parses all SCIP Index message fields used for edge resolution: `occurrences` (range, symbol, symbol_roles, enclosing_range), `symbols` (relationships → is_implementation).
  - The decoder requires no protobuf runtime dependency — it is a standalone wire-format reader supporting varint, length-delimited, packed, and 32/64-bit fields.
  - Files named `index.scip` in the project root are auto-discovered; any `*.scip` file is also accepted (first found wins).
  - Malformed index files produce a logged warning and a graceful fallback to string matching — never a crash.
- **Priority:** P0 (ship-blocking)

### 6.2 Graph Refinement Pass

**Requirement SCIP-2:** NeuralMind shall replace heuristic `calls` and `inherits` edges with SCIP-resolved edges for files covered by the SCIP index, while preserving all other graph structure.

- **Acceptance:**
  - Heuristic edges (`calls`, `inherits`) for files present in the SCIP index are removed.
  - SCIP-resolved edges are inserted in their place with `confidence: "PRECISE"` (vs `"EXTRACTED"` for heuristic edges).
  - Edges for files NOT in the SCIP index are left untouched.
  - Nodes (`file`, `class`, `function`, `assignment`), `contains` edges, `imports_from` edges, `rationale` edges, and community assignments are preserved unchanged.
  - SCIP symbol resolution uses class-aware key matching: a method `handle()` in class `AuthService` resolves to the correct `AuthService.handle` node even when another class also defines `handle()`.
  - Deduplication: no duplicate edges for the same source/target/relation.
- **Priority:** P0 (ship-blocking)

### 6.3 Config Toggle — Off by Default

**Requirement SCIP-3:** SCIP precision shall be off by default, gated behind an environment variable, to preserve backward compatibility.

- **Acceptance:**
  - `NEURALMIND_PRECISION=1` (or any truthy value) enables the pass.
  - When unset/`0`/`false`: the graph is produced identically to a pre-v2.1 build.
  - When set but no `*.scip` file is found: the graph is produced identically to a disabled build (no error, no warning beyond a debug log).
  - A printed status line tells the user how many edges were replaced on each build run.
  - The `ScipConfig` dataclass has `enabled: bool = False` as its default.
- **Priority:** P0

### 6.4 Language Coverage

**Requirement SCIP-4:** The SCIP precision pass shall support any language for which a `scip-cli` indexer exists. Minimum viable coverage:

| Language | SCIP Detection | Edge Types Resolved | Notes |
|----------|---------------|---------------------|-------|
| TypeScript | `scip-typescript` | calls, inherits, references | Highest-priority language |
| Go | `scip-go` | calls, inherits (interface impl) | Implicit interface detection is unique value |
| Rust | `scip-rust` | calls, inherits | Cross-crate resolution |
| Java | `scip-java` | calls, inherits | Enterprise requirement |
| C/C++ | `scip-clang` | calls, inherits | Systems code requirement |
| Python | `scip-python` | calls, inherits | Currently experimental support; tree-sitter is primary |

- **Acceptance:** The SCIP reader is language-agnostic — it reads the protobuf schema regardless of which indexer produced it. Language-specific handling is limited to symbol descriptor parsing (handling `#` for member-of-type vs native paths). No language-specific code is needed in the precision pass itself.
- **Priority:** P1

### 6.5 Incremental Build Integration

**Requirement SCIP-5:** The SCIP precision pass shall re-run on every `neuralmind build` and every incremental `neuralmind update-files` call.

- **Acceptance:**
  - On full build (`build_graph`): `maybe_refine` runs after tree-sitter graph construction, before writing to `graph.json`.
  - On incremental update (`update_files`): `maybe_refine` re-runs on the merged graph.
  - The SCIP index is re-read from disk on each invocation (it's small — typically < 10MB — and protobuf parsing is fast).
  - Diagnostic output shows: `"[neuralmind] SCIP precision pass: +43 calls, +12 inherits (replaced 31 heuristic calls, 8 inherits across 27 documents)"`.
- **Priority:** P1

### 6.6 Audit and Observability

**Requirement SCIP-6:** SCIP pass statistics must be surfaced in build output and storable for CI evaluation.

- **Acceptance:**
  - `RefineStats` dataclass tracks: `calls_added`, `inherits_added`, `heuristic_calls_removed`, `heuristic_inherits_removed`, `documents` (files covered).
  - Stats are printed to stderr on every build run.
  - A build with SCIP enabled sets `graph["precision"] = "scip"` in the output JSON for downstream tooling.
  - Failed SCIP parse (malformed index) writes a warning to stderr but does not fail the build.
- **Priority:** P2

## 7. What This Is NOT

- **Not an LSP integration.** LSP provides similar information but is designed for interactive use (per-file, incremental, stateful server process). SCIP is batch-oriented and side-effect-free — the right fit for a build-time graph producer.
- **Not a replacement for tree-sitter.** Tree-sitter provides the structural skeleton (files, classes, functions, assignments). SCIP provides edges between those nodes. Both are needed; we are not removing tree-sitter.
- **Not a cross-repo SCIP merge.** The current pass operates on a single index per project. Multi-repo SCIP merging (combining indexes from workspace dependencies) is a future feature (v2.2 candidate).
- **Not a SCIP indexer replacement.** We do not produce SCIP indexes — we consume them. The user is expected to run `scip-cli` as a separate step (or we may bundle convenience scripts in a future release).

## 8. Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| SCIP symbol doesn't map to tree-sitter node | High | Low (skipped silently) | Log at debug level; no dangling edges produced |
| SCIP index stale vs source code | Medium | Medium | User responsibility to regenerate SCIP index before build; document in workflow |
| Protobuf schema evolves (new field numbers) | Low | Low | Wire-format decoder reads by field number; unknown fields are silently skipped |
| SCIP index is very large (>100MB) | Low | Medium | Streaming parse (future); for v2.1, scan threshold: warn if >50MB |
| Two indexers produce different symbol descriptors for same language | Medium | Low | Symbol parser handles both `#method` and `/method` patterns |
| `NEURALMIND_PRECISION` env var conflicts with `neuralmind-backend.yaml` config | Low | Low | v2.1 uses env var only; config file support is v2.2 |
