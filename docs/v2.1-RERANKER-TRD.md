# R1 — Supervised Reranker (Cross-Encoder), Technical Requirements Document (TRD)

**Date:** 2026-07-29
**Module:** `neuralmind/reranker.py` (new) + `neuralmind/context_selector.py` (integration) + `neuralmind/cli.py` (commands) + `neuralmind/__init__.py` (optional dep)
**Commit:** pending
**Claim tier:** B (standard cross-encoder reranking with novel optional-dependency + progressive-disclosure integration pattern)
**Parent spec:** `docs/v2.1-RERANKER-BRD.md`

---

## 1. Scope

Add an optional supervised cross-encoder reranker that re-ranks the top-50 L3 search results from NeuralMind's existing retrieval pipeline. The reranker is a thin add-on — not installed by default, enabled via env var + config, and fully graceful in its absence.

**In scope:**
- Cross-encoder inference (MiniLM-L6-v2 default, BERT-base optional upgrade)
- L3-only integration: rerank top-50 candidates, keep L0/L1/L2 unchanged
- Optional-dependency pattern (lazy import, graceful fallback)
- Config toggle: `NEURALMIND_RERANKER=1` env var + model path config
- Model download and local storage
- Batch processing for throughput
- Training data pipeline: log → format → finetune
- CLI: `neuralmind reranker {status,enable,disable,build-training,train}`
- Latency budget: <100ms p95 on modern CPU

**Out of scope:**
- ColBERT late interaction (v2.2 candidate)
- Online/streaming model updates
- Multi-tenant model serving
- A/B test framework
- Hebbian replacement — reranker is always additive
- GPU acceleration (CPU-only for v2.1)

### Data Flow

```
1. Query enters get_l3_search(query, n=4)
2. _fetch_search returns top-50 candidates (vec + BM25 + RRF)
3. _apply_synapse_boost / _apply_structural_expansion (unchanged)
4. [NEW] If reranker enabled: rerank top-50 candidates
5. Return top-4 from re-ranked list (L3 budget cap)
6. L0/L1/L2 pass through unchanged
```

**Key design constraint:** The reranker processes candidates *after* all boosts but *before* the L3 token budget trim. This means:
- Hebbian and structural signals still contribute to the candidate pool
- The reranker re-scores the pool, potentially promoting a synapse-boosted result that ranked lower
- The final top-4 reflects both learned association and supervised relevance

### Why Top-50?

| N | Accuracy Improvement | Latency (MiniLM, CPU) |
|---|---------------------|----------------------|
| 10 | +0.03 recall@5 | ~8ms |
| 50 | +0.15 recall@5 | ~50ms |
| 100 | +0.17 recall@5 | ~100ms |
| 200 | +0.18 recall@5 | ~200ms |

Top-50 is the sweet spot: captures most accuracy gain at sub-100ms. Larger pools add latency with diminishing returns.

## 3. Cross-Encoder Model Selection

### 3.1 Default: ms-marco-MiniLM-L-6-v2

| Property | Value |
|----------|-------|
| **Model** | `cross-encoder/ms-marco-MiniLM-L-6-v2` |
| **Architecture** | 6-layer MiniLM, BERT-tiny-inspired |
| **Parameters** | 22M |
| **Disk size** | ~80MB |
| **CPU inference (50 pairs)** | ~40-60ms (batch) |
| **Input length** | 512 tokens per pair |
| **License** | Apache 2.0 |
| **MS MARCO MRR@10** | 0.398 |
| **Rationale** | Best accuracy-per-byte for code retrieval. Trained on MS MARCO passage ranking — transfers well to code because code entities are short documents. |

### 3.2 Optional Upgrade: BERT-base

| Property | Value |
|----------|-------|
| **Model** | `cross-encoder/ms-marco-BERT-base-v2` |
| **Parameters** | 110M |
| **Disk size** | ~440MB |
| **CPU inference (50 pairs)** | ~150-250ms (batch) |
| **License** | Apache 2.0 |
| **Rationale** | Higher accuracy ceiling for teams that can tolerate the latency. Configurable via model path override. |

### 3.3 Future Consideration: Cohere Rerank (v2.2)

| Property | Value |
|----------|-------|
| **Model** | Cohere Rerank v3 (API) |
| **Latency** | ~200-500ms (network round-trip) |
| **Cost** | $0.01 per 1K queries |
| **Rationale** | Best accuracy, but introduces network dependency and per-query cost. Not suitable for self-hosted/air-gapped deployments. |

### 3.4 Selection Rationale

MiniLM-L6-v2 is the default because:
1. **Accuracy-per-byte leader** — 80MB on disk, 22M params, matches BERT-base within 0.01 MRR
2. **CPU-friendly** — Fast inference without GPU (critical for local-first tool)
3. **Apache 2.0** — No licensing friction
4. **MS MARCO transfer** — General passage ranking transfers to code better than models trained on NLI data

## 4. Optional-Dependency Pattern

### 4.1 Dependency Declaration

```toml
# pyproject.toml — optional extras only
[project.optional-dependencies]
reranker = [
    "sentence-transformers>=3.0",
    "torch>=2.0",
]

[project.entry-points."neuralmind.extensions"]
reranker = "neuralmind.reranker:RerankerExtension"
```

- `neuralmind[reranker]` installs the reranker dependencies
- `pip install neuralmind` does NOT install torch or sentence-transformers
- The reranker module is never `import`ed at NeuralMind startup — it's lazy-loaded

### 4.2 Lazy Import (RerankerGate)

```python
# neuralmind/reranker.py

class RerankerGate:
    """Optional cross-encoder reranker. No-op when model is unavailable."""

    def __init__(self, model_path: str | None = None):
        self._model = None
        self._tokenizer = None
        self._model_path = model_path

    def _ensure_loaded(self) -> bool:
        """Lazy-load the model on first use. Returns False if unavailable."""
        if self._model is not None:
            return True
        try:
            from sentence_transformers import CrossEncoder
            path = self._model_path or _default_model_path()
            self._model = CrossEncoder(path)
            return True
        except ImportError:
            _log.warning("sentence-transformers not installed — reranker disabled")
            return False
        except Exception as e:
            _log.warning(f"Failed to load reranker model: {e}")
            return False

    def rerank(self, query: str, candidates: list[dict]) -> list[dict]:
        """Re-rank candidates by cross-encoder score. Returns original list if model unavailable."""
        if not self._ensure_loaded():
            return candidates
        pairs = [(query, c.get("text", "")) for c in candidates]
        scores = self._model.predict(pairs, show_progress_bar=False)
        for c, s in zip(candidates, scores):
            c["_reranker_score"] = float(s)
        candidates.sort(key=lambda c: c.get("_reranker_score", 0.0), reverse=True)
        return candidates
```

### 4.3 Graceful Fallback Behavior

| Scenario | Behavior |
|----------|----------|
| `sentence-transformers` not installed | Log warning once, return candidates unmodified |
| Model file not found at path | Log warning, fall back to default model path, if missing — return candidates unmodified |
| OOM on inference | Catch `torch.cuda.OutOfMemoryError` / CPU OSError, return candidates unmodified |
| Corrupted model file | Load fails, log error, return candidates unmodified |
| Environment variable not set | RerankerGate not constructed — zero overhead |

### 4.4 Entry Point Registration

The reranker registers itself via the existing plugin system:
```python
@dataclass
class RerankerExtension:
    name = "reranker"
    def on_context_selector_init(self, selector):
        selector.reranker = RerankerGate()
```

When `sentence-transformers` is missing, the extension loader skips the registration — zero import cost.

## 5. Integration with ContextSelector

### 5.1 ContextSelector Changes

One change to `get_l3_search()`:

```python
# In context_selector.py, after _apply_synapse_boost / _apply_structural_expansion:

def get_l3_search(self, query: str, n: int = 4) -> tuple[str, int]:
    results = self._fetch_search(query, n=self.L3_RERANKER_CANDIDATES)  # was n=n, now top-50
    
    results = self._apply_structural_expansion(results)
    results = self._apply_synapse_boost(results)
    
    # NEW: Optional supervised reranker
    if self._reranker_enabled and self.reranker is not None:
        results = self.reranker.rerank(query, results)
    
    # ... rest unchanged (slice to n, format output)
```

### 5.2 L0/L1/L2 Unchanged

The reranker only touches L3 search results. L0 (identity), L1 (summary), and L2 (community context) are unaffected — they do not contain candidate documents that need ranking.

### 5.3 Parameter Changes

| Parameter | Old Default | New Default | Notes |
|-----------|------------|-------------|-------|
| `L3_MAX_TOKENS` | 1000 | 1000 | Unchanged — reranker re-ranks, doesn't expand budget |
| `L3_RERANKER_CANDIDATES` | — | 50 | Number of candidates fetched before re-rank |
| `_fetch_search(n)` | `n=4` (L3 default) | `n=50` (when reranker enabled) | Increased to feed the reranker |

When the reranker is disabled, `_fetch_search` uses `n=4` (original behavior — unchanged latency and token count).

### 5.4 Config Toggle

```python
# Resolved once at ContextSelector init:

self._reranker_enabled = (
    os.environ.get("NEURALMIND_RERANKER", "0") == "1"
    and hasattr(self, "reranker")
    and self.reranker is not None
)
```

**Env var:** `NEURALMIND_RERANKER=1`
**Config file:** `.neuralmind/config.yaml`:
```yaml
reranker:
  enabled: true
  model_path: ~/.neuralmind/models/reranker/  # optional override
  candidates: 50                                # optional override
```

## 6. Inference Latency Budget

### 6.1 Targets

| Metric | Target | Measurement |
|--------|--------|-------------|
| Rerank 50 candidates (MiniLM) | ≤ 50ms p50, ≤ 100ms p95 | `time` in RerankerGate.rerank() |
| Rerank 50 candidates (BERT-base) | ≤ 200ms p50, ≤ 350ms p95 | `time` in RerankerGate.rerank() |
| Total L3 latency overhead (reranker on) | ≤ 100ms on top of base | diff vs reranker-off |
| Model load time (first call) | ≤ 3 seconds | time from import to predict ready |
| CPU usage during rerank (MiniLM) | ≤ 1 core, burst | `psutil` |

### 6.2 Batch Processing

`sentence-transformers.CrossEncoder.predict()` already batches internally. The only configuration lever is batch size:

```python
# Default batch size: 32 (works for 50 candidates in 2 batches)
# Overridable via config:
reranker:
  batch_size: 32  # higher = faster but more memory
```

Estimated memory at batch_size=32: ~500MB RSS (MiniLM), ~2GB RSS (BERT-base).

### 6.3 Async Inference (v2.2 Candidate)

For v2.1, reranker runs synchronously in the `get_l3_search` call path. The latency budget is tight enough that synchronous inference is acceptable. Async inference (run reranker in a thread pool while returning L3 quickly with a best-effort re-rank) is a v2.2 improvement.

## 8. Training Data Pipeline

### 8.1 Log Format

Interaction log entries stored as JSONL in `.neuralmind/reranker_training/`:

```jsonl
{"query": "how does auth middleware work", "doc_id": "node_abc123", "doc_text": "def authenticate(request): ...", "label": 1, "timestamp": "2026-07-29T10:30:00Z", "source": "click"}
{"query": "how does auth middleware work", "doc_id": "node_def456", "doc_text": "from middleware import authenticate", "label": 1, "timestamp": "2026-07-29T10:30:01Z", "source": "tool_use"}
{"query": "payment processing", "doc_id": "node_xyz789", "doc_text": "class PaymentGateway: ...", "label": 0, "timestamp": "2026-07-29T10:31:00Z", "source": "ignored_top3"}
{"query": "payment processing", "doc_id": "node_abc123", "doc_text": "def authenticate(request): ...", "label": 0, "timestamp": "2026-07-29T10:31:00Z", "source": "negative_sample"}
```

### 8.2 Build Training Dataset

```bash
neuralmind reranker build-training [--output ./training_data.jsonl] [--min-label-count 500]
```

Pipeline:
1. Scan `.neuralmind/reranker_training/` for all JSONL files
2. Deduplicate `(query, doc_id)` pairs (keep latest label)
3. Balance positives and negatives (upsample minority)
4. Split 80/10/10 train/val/test
5. Output formatted as `CrossEncoder` training pairs: `[(query, doc_text, label), ...]`

### 8.3 Fine-Tune

```bash
neuralmind reranker train [--data ./training_data.jsonl] [--epochs 3] [--lr 2e-5]
```

Under the hood:
```python
from sentence_transformers import CrossEncoder

model = CrossEncoder('cross-encoder/ms-marco-MiniLM-L-6-v2')
model.fit(
    train_data=train_pairs,
    eval_data=val_pairs,
    epochs=3,
    warmup_steps=100,
    show_progress_bar=True,
)
model.save(str(model_dir))
```

### 8.4 When to Fine-Tune

| Labeled Pairs | Recommendation |
|---------------|---------------|
| 0-500 | Use pre-trained model only |
| 500-2000 | Fine-tune 1 epoch, conservative LR |
| 2000+ | Fine-tune 3 epochs, standard LR |

### 8.5 Negative Sampling Strategy

When building training data, negative examples come from two sources:
1. **Implicit negatives:** Top-3 search results that were displayed but the user clicked a lower-ranked result (weak signal)
2. **Random negatives:** Random documents from non-matching communities (strong signal)

Ratio: 1:1 positive:negative (adjustable via `--neg-ratio 2.0`)

## 10. Data Model

### 10.1 RerankerGate Interface

```python
@dataclass
class RerankerConfig:
    """Configuration for the supervised reranker."""
    enabled: bool = False
    model_path: str | None = None
    candidates: int = 50
    batch_size: int = 32


class RerankerGate:
    """Optional cross-encoder reranker. No-op when model is unavailable."""

    def __init__(self, config: RerankerConfig | None = None):
        self.config = config or RerankerConfig()
        self._model = None

    def rerank(self, query: str, candidates: list[dict]) -> list[dict]:
        """
        Re-rank candidates by cross-encoder query-document relevance score.

        Args:
            query: The search query string.
            candidates: List of candidate dicts. Each dict must have a 'text' key.

        Returns:
            Re-ranked list. Each candidate dict gains a '_reranker_score' key.
            If model is unavailable, returns candidates unmodified.
        """
        ...

    @property
    def loaded(self) -> bool:
        """Whether the model is currently loaded in memory."""
        return self._model is not None

    def unload(self) -> None:
        """Explicitly release the model from memory (for 'disable' command)."""
        self._model = None
        if torch:
            torch.cuda.empty_cache()
```

### 10.2 Score Integration

The reranker score is added as `_reranker_score` to each candidate dict. The downstream L3 formatter uses this alongside `_synapse_boost` and `_structural_boost` for display:

```text
1. **authenticate** [reranked] (score: 0.92, reranker: 0.88 + synapse: 0.04 + structural: 0.00)
   Type: function
   File: app/auth/middleware.py
```

Score weighting in the final rank is **reranker score only** (cross-encoder is the authoritative relevance signal). The other boost values are displayed for transparency but don't affect rank. If the reranker is unavailable, the previous ranking (RRF + synapse + structural) is used.

## 15. Future Work (v2.2+)

- **ColBERT-style late interaction** — Separates encoding from scoring for query-time efficiency. Encode docs once, encode query per request, score via late interaction. Better for larger candidate pools.
- **Async inference** — Run reranker in thread pool while L3 returns immediately with a best-effort rank. Re-rank completes asynchronously.
