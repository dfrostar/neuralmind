## 1. Scope

Add an optional cross-encoder reranker that re-ranks first-stage candidates before L2/L3 fusion. The reranker uses ONNX runtime (no PyTorch required), falls back heuristically when no ONNX model is available, and self-disables when latency budgets are exceeded.

**In scope (what the actual code does):**
- ONNX-compatible `CrossEncoderReranker` class (`import onnxruntime as ort`)
- `HeuristicReranker` with token-overlap (Jaccard-like) scoring for model-less fallback
- `RerankConfig` dataclass with `enabled`, `max_latency_ms`, `top_n`, `model_path`
- Environment variables: `NEURALMIND_RERANK`, `NEURALMIND_RERANK_MAX_MS`, `NEURALMIND_RERANK_MODEL`
- Latency budget tracking via running average (exponential moving window per query)
- Self-disabling when running average exceeds `max_latency_ms`
- Lazy ONNX model loading (`onnxruntime.InferenceSession`)
- Fail-open semantics: missing model → heuristic fallback, missing deps → heuristic fallback
- `stats()` method exposing latency, model load state, and query count
- Standalone module — no integration with `context_selector.py` (v2.1 is additive plumbing only)

**Out of scope (not in actual code, deferred to future):**
- Plugin extension system — no `RerankerExtension` or entry-point registration
- Training pipeline — no `reranker build-training` or `reranker train` CLI commands
- HuggingFace model download — no `snapshot_download` or `huggingface_hub` dependency
- ContextSelector integration — no `L3_RERANKER_CANDIDATES` or `get_l3_search()` hook
- GPU acceleration — CPU-only ONNX runtime
- Batch processing optimizer — module scores one query at a time
- ColBERT late interaction (v2.2 candidate)
- Async inference
- Fine-tuning or online learning

### Data Flow

```
1. Caller (e.g. embedder.py in future) calls reranker.rerank(query, candidates)
2. If not config.enabled: return [('', 0.0)] for each candidate (no-op)
3. If running avg latency > max_latency_ms: return candidates unmodified (self-disable)
4. For each candidate: score_pair(query, candidate)
   a. Try ONNX model if loaded → returns cross-encoder score
   b. Fallback to HeuristicReranker.token_overlap score
5. Sort candidates by score descending
6. Update running latency average
7. Return top-k scored candidates as list[(str, float)]
```

### Key Design Constraint

The reranker is a **standalone module** with no dependencies on `context_selector.py`, `embedder.py`, or any other NeuralMind module. It exposes a simple `rerank(query, candidates) → list[tuple[str, float]]` interface. Integration with the retrieval pipeline happens at the call site — the reranker itself is pure business logic.

This decoupling means:
- The reranker can be unit-tested independently
- It can be replaced with a different scoring backend without touching the retrieval pipeline
- The latency tracking is local to the reranker instance
- It works equally well as a pre-filter or post-filter

## 3. Cross-Encoder Model

### 3.1 Default: ms-marco-MiniLM (ONNX-compatible)

| Property | Value |
|----------|-------|
| **Model** | `cross-encoder/ms-marco-MiniLM-L-6-v2` (ONNX export) |
| **Runtime** | `onnxruntime` — no PyTorch required at inference |
| **Architecture** | 6-layer MiniLM, BERT-tiny-inspired |
| **Parameters** | 22M |
| **CPU inference (per pair)** | ~1-2ms (batched implicitly by caller) |
| **Input length** | 512 tokens per pair |
| **License** | Apache 2.0 |
| **Rationale** | ONNX gives CPU-native inference without PyTorch's 800MB install. MiniLM fits ONNX well. ms-marco trains on passage ranking — transfers to code. |

### 3.2 Model Loading (Lazy)

```python
def _load_model(self) -> None:
    if self._model is not None:
        return
    model_path = self.config.model_path or os.environ.get("NEURALMIND_RERANK_MODEL")
    if not model_path:
        return
    try:
        import onnxruntime as ort
        self._model = ort.InferenceSession(str(model_path))
    except Exception:
        self._model = None  # Fail-open: heuristic fallback used
```

Key behaviors:
- Model is **not loaded** at construction time
- `_load_model()` is called on every `score_pair()` — lightweight check if already loaded
- Missing `model_path` → returns immediately (no error, no warning)
- `onnxruntime` not installed → exception caught, `self._model` stays `None`
- Corrupted model file → exception caught, `self._model` stays `None`
- All error paths fall through to heuristic scoring — **zero query failures**

### 3.3 Current Limitation (v2.1)

The ONNX model path is wired, but the actual ONNX inference call is a stub that defers to heuristic scoring:

```python
def score_pair(self, query: str, candidate: str) -> float:
    self._load_model()
    if self._model is None:
        return self._heuristic.score_pair(query, candidate)
    # Note: real inference requires tokenization aligned with the model.
    # For now, this is a stub for the ONNX interface (model-specific).
    return self._heuristic.score_pair(query, candidate)
```

Full ONNX inference (tokenization + model-specific preprocessing + `self._model.run()`) is deferred to a follow-up commit. The architecture and plumbing are in place — the model loads, the fallback works, and the latency budget is tracked. Adding the actual ONNX scoring function is a contained change.

## 4. HeuristicReranker (No-Model Fallback)

### 4.1 Scoring Algorithm

When no ONNX model is available (whether because `model_path` is unset, `onnxruntime` is not installed, or the model file is corrupted), the `HeuristicReranker` provides a token-overlap score:

```python
def score_pair(self, query: str, candidate: str) -> float:
    from .sparse import tokenize

    q_tokens = set(tokenize(query))
    c_tokens = set(tokenize(candidate))
    if not q_tokens or not c_tokens:
        return 0.0
    # Jaccard-like overlap weighted by query coverage.
    intersection = q_tokens & c_tokens
    return len(intersection) / max(len(q_tokens), 1)
```

### 4.2 Characteristics

| Property | Value |
|----------|-------|
| **Dependencies** | Pure stdlib + `neuralmind.sparse.tokenize` |
| **Latency** | < 0.1ms per pair (negligible) |
| **Strengths** | Fast, zero-dependency, works for any language |
| **Weaknesses** | No semantic understanding — purely lexical overlap |
| **Use case** | Cold-start or when ONNX model unavailable |

### 4.3 When Each Path Is Used

| Scenario | Scoring Path | Rationale |
|----------|-------------|-----------|
| `model_path` unset & no env var | Heuristic | No model to load |
| `model_path` set, `onnxruntime` missing | Heuristic (fail-open) | Dep not installed |
| `model_path` set, model loads OK | ONNX (stub → heuristic for now) | Full ONNX inference deferred |
| `model_path` set, load fails | Heuristic (fail-open) | Graceful degradation |

## 6. CrossEncoderReranker (Public API)

### 6.1 Class Interface

```python
class CrossEncoderReranker:
    def __init__(self, config: RerankConfig | None = None)
    def score_pair(self, query: str, candidate: str) -> float
    def rerank(self, query: str, candidates: list[str], *, top_k: int | None = None) -> list[tuple[str, float]]
    def stats(self) -> dict
```

### 6.2 Constructor

```python
def __init__(self, config: RerankConfig | None = None):
    self.config = config or RerankConfig()
    self._model = None            # ONNX InferenceSession, lazy-loaded
    self._heuristic = HeuristicReranker()
    self._avg_latency_ms: float = 0.0      # Running average
    self._num_queries: int = 0              # Query count for EMA
```

### 6.3 `score_pair(query, candidate) → float`

Scores a single query-candidate pair (see §3.3 for the current stub behavior).

### 6.4 `rerank(query, candidates, *, top_k) → list[tuple[str, float]]`

The main entry point:

```
1. If not self.config.enabled:
   → return list(zip(candidates, [0.0] * len(candidates)))
   (No-op mode — zero latency, no scoring)

2. If self._avg_latency_ms > self.config.max_latency_ms:
   → return list(zip(candidates, [0.0] * len(candidates)))
   (Self-disabled — budget exceeded, preserve caller's original ordering)

3. For each candidate: score_pair(query, candidate)
   → scored list of (candidate, score)

4. Sort scored list by score descending

5. Update latency tracking:
   elapsed_ms = (time.monotonic() - start) * 1000.0
   self._num_queries += 1
   self._avg_latency_ms += (elapsed_ms - self._avg_latency_ms) / self._num_queries

6. Return scored[:top_k]
```

### 6.5 `stats() → dict`

Returns a snapshot of internal state:

```python
{
    "enabled": True/False,
    "avg_latency_ms": 12.34,
    "num_queries": 42,
    "model_loaded": True/False,
    "max_latency_ms": 50.0,
}
```

This is the only introspection API. No `status` CLI command exists yet — callers inspect the reranker programmatically.

## 7. Latency Budget & Self-Disabling

### 7.1 Motivation

The reranker must not degrade query latency for the overall NeuralMind system. The latency budget ensures that a slow model (e.g. on a resource-constrained machine) is silently skipped rather than adding tens or hundreds of milliseconds per query.

### 7.2 Algorithm

```
Running average: exponential moving average (EMA)
Initial: _avg_latency_ms = 0.0
On each query:
    elapsed_ms = query_end - query_start
    _num_queries += 1
    _avg_latency_ms += (elapsed_ms - _avg_latency_ms) / _num_queries
```

This is a cumulative average (not windowed), which means:
- First few queries dominate the average
- As `_num_queries` grows, new measurements have diminishing impact
- A single slow query won't permanently disable the reranker — many fast queries will bring the average back down

### 7.3 Disable Threshold

| Condition | Behavior |
|-----------|----------|
| `_avg_latency_ms ≤ max_latency_ms` | Normal scoring |
| `_avg_latency_ms > max_latency_ms` | Return candidates unmodified with zero scores |
| `max_latency_ms = 0.0` | Effectively disabled on first query (avg starts at 0 > 0? No — `avg > max` is false when avg=0, max=0. First query runs normally; subsequent behaviour depends on actual latency. To fully disable, set `enabled=False`.) |

### 7.4 Recovery

The self-disable is **not sticky** across reranker re-initialization. Each `CrossEncoderReranker` instance starts with a fresh average. If the caller creates a new reranker (or context switches to a less loaded machine), the budget resets.

### 7.5 Targets

| Metric | Target | Measurement |
|--------|--------|-------------|
| Rerank overhead (heuristic fallback) | < 1ms | `time.monotonic()` delta in `rerank()` |
| ONNX inference target (50 pairs) | ≤ 50ms p50 | Per-query latency tracking |
| Self-disable activation threshold | 50ms p50 (configurable) | `max_latency_ms` config field |
| First query overhead (no model) | < 0.1ms | Module-level import cost (stdlib only) |

### 9.1 With embedder.py (Future)

The reranker is designed to slot into `embedder.py`'s retrieval path. Expected integration:

```python
# In embedder.py (future):
from neuralmind.rerank import CrossEncoderReranker, RerankConfig

config = RerankConfig.from_env()
reranker = CrossEncoderReranker(config) if config.enabled else None

def query(query: str):
    candidates = first_stage_retrieval(query)
    if reranker:
        scored = reranker.rerank(query, [c.text for c in candidates])
```

### 10.1 Latency

| Scenario | Budget | Notes |
|----------|--------|-------|
| Import cost | < 1ms | Module is pure Python + stdlib dataclasses. `onnxruntime` not imported. |

### 10.2 Memory

| Scenario | RSS Overhead | Notes |
|----------|-------------|-------|
| Module imported, no reranker instantiated | ~0KB | `import rerank` adds nothing to memory |
| HeuristicReranker instantiated | ~1KB | Two empty attribute dicts |
| CrossEncoderReranker with ONNX model loaded | ~200-500MB | ONNX model + runtime overhead |
| After self-disable (avg exceeded) | ~0 additional | Latency tracking floats only |

### 10.3 Reliability

| Scenario | Behavior |
|----------|----------|
| `onnxruntime` not installed | Fail-open to heuristic fallback |
| Model file not found | Fail-open to heuristic fallback |
| Model file corrupted | `ort.InferenceSession()` raises → caught → heuristic fallback |
| OOM during ONNX load | OS raises → caught → heuristic fallback |
| `sparse.tokenize()` fails | `score_pair` catches (not explicitly — TODO: harden) and returns 0.0 |

### 10.4 Zero Import Cost

`from neuralmind.rerank import CrossEncoderReranker` does NOT:
- Import `onnxruntime` (lazy-loaded inside `_load_model()`)
- Import `torch` (not used at all — ONNX runtime is PyTorch-free)
- Load any model file
- Access disk or network

```python

# In _load_model():
```

### 13.3 Fail-Open Error Handling

All ONNX-related failures are caught by a bare `except Exception`:

```python
try:
    import onnxruntime as ort
    self._model = ort.InferenceSession(str(model_path))
except Exception:
    self._model = None
```

This is intentionally broad — any error during model loading (missing file, corrupt file, OOM, permission denied, wrong ONNX opset version) degrades gracefully to heuristic fallback rather than crashing the query.

### 13.4 Tokenizer Dependency

The `HeuristicReranker` imports `tokenize` from `neuralmind.sparse`:

```python
from .sparse import tokenize
```

This is the same tokenizer used elsewhere in NeuralMind for BM25 keyword extraction. It ensures consistent tokenization across the retrieval pipeline.

## 14. Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| ONNX inference stub not replaced before v2.1 release | Medium | Medium | Heuristic fallback produces usable results. No users hit a broken ONNX path. Deferred to immediate follow-up commit. |
| `sparse.tokenize()` changes signature | Low | Medium | `HeuristicReranker` uses it directly — import would fail at load. Unit tests catch this. |
| Running average never recovers from first slow query | Low | Low | Cumulative average: a single slow query among many fast ones has diminishing impact. If the first query is slow, the second must also be slow — or the average drops. |
