## 1. Business Problem

Prior to G4, `build_graph()` re-extracted every file on every build. For a 10K-line repo with one file changed, the entire tree gets reparsed — wasting minutes and producing a completely new graph (defeating the purpose of G3's community ID carry-over).

G4 skips unchanged files by tracking content hashes. Only changed files + their transitive importers get re-extracted.

## 2. Objectives

| # | Objective | Metric |
|---|-----------|--------|
| O1 | Skip content-unchanged files | `scan_files()` detects unchanged by mtime + SHA-256 |
| O2 | Transitively invalidate importers | `get_changed_with_dependents()` adds importers of changed files to re-extraction set |
| O3 | Drop dangling edges on rename/delete | Edges to non-existent nodes pruned in `build_graph()` incremental path |
| O4 | Build time < 10% of full build for small changes | Measured on test fixtures |

## 4. Honest Scope

G4 v1 implements basic file-level skipping + reverse-edge invalidation. It does NOT implement:
- Symbol-level incremental re-extraction (still re-extracts the entire file if any symbol changed)
- Concurrent build locking (no `flock` on cache write)
- Persistent `community` ID metadata across cache invalidation events

These are documented in `docs/specs/G4-TRD.md` as future work.
