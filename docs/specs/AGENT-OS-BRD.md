## 1. Business Need

NeuralMind runs as a single-tenant system. A team indexing one codebase has no concept of "business," "tenant," or "operator." This is fine for individuals. It fails for:

- **Agencies** running NeuralMind on multiple client codebases from one server
- **Multi-business operators** (e.g., Cheval-Volant owns Level2Logic + CyberSentinel + NeuralMind — three separate products, three separate teams)
- **Regulated environments** requiring audit trails, role separation, and anomaly detection on metrics streams

The Agent OS adds:
1. **Tenant isolation** — projects grouped by business, with RBAC
2. **Signal detection** — automatic anomaly detection on latency, answerability, token budgets
3. **Governance** — RBAC (admin/operator/viewer), audit logging, experiment promote/rollback
4. **Self-improvement loop** — signal → diagnose → experiment → promote/rollback

## 2. Stakeholders

| Stakeholder | Role | Need |
|-------------|------|------|
| Tenant admin | `admin` | Create tenant, assign roles, manage projects, view audit trail |
| Tenant operator | `operator` | Manage projects, view signals, run experiments |
| Tenant viewer | `viewer` | Read-only dashboard + signals |
| System operator | infra | Deploy, backup, monitor across tenants |

## 3. Business Requirements

### FR-1: Tenant Lifecycle
- FR-1.1: Create tenant with `tenant_id` (URL-safe slug), `name`, `tier`, optional `admin_email`
- FR-1.2: Delete tenant (admin-only, irreversible)
- FR-1.3: Tenants persisted as JSON files in `~/.config/neuralmind/tenants/`
- FR-1.4: Tenant registry reloadable from disk (no restart)

### FR-2: Project Assignment
- FR-2.1: Add project path to tenant (operator+)
- FR-2.2: Remove project from tenant (admin-only)
- FR-2.3: Hard invariant: one project → one tenant (no cross-tenant leakage)
- FR-2.4: Resolve tenant from project path (for daemon routing)

### FR-3: RBAC
- FR-3.1: Roles: `admin` (full), `operator` (manage), `viewer` (read-only)
- FR-3.2: Permission-based (not role-name-based) enforcement
- FR-3.3: Decorator `@require_permission(Permission.X)` for enforcement
- FR-3.4: Fail-closed: unknown roles default to viewer
- FR-3.5: Email normalized to lowercase on all operations

### FR-4: Signal Detection
- FR-4.1: Page-Hinkley anomaly detection (no fixed thresholds)
- FR-4.2: Per-metric state (running mean, running std, cumulative deviation)
- FR-4.3: Severity levels: INFO, LOW, MEDIUM, HIGH, CRITICAL
- FR-4.4: Cooldown to prevent alert spam
- FR-4.5: Reset per-metric or all-metrics

### FR-5: Experiment Governance
- FR-5.1: A/B experiment runner with baseline + candidate values
- FR-5.2: `higher_is_better` support (throughput vs latency)
- FR-5.3: Promote threshold (default 5%), rollback threshold (default -3%)
- FR-5.4: Deterministic verdict: PROMOTED / ROLLED_BACK / REJECTED
- FR-5.5: Experiment history (newest-first)

### FR-6: Audit Trail
- FR-6.1: JSONL audit log per-action (`~/.config/neuralmind/agent-os-audit.jsonl`)
- FR-6.2: Every permission grant/denied logged
- FR-6.3: Every role assignment / project change logged
- FR-6.4: Fail-open: audit logging never blocks operations

### FR-7: Daemon API
- FR-7.1: Tenant CRUD endpoints (`POST/GET/DELETE /api/agent-os/tenants[/id]`)
- FR-7.2: Project assignment endpoints (`POST/DELETE /api/agent-os/tenants/{id}/projects`)
- FR-7.3: RBAC endpoints (`POST /api/agent-os/tenants/{id}/rbac`)
- FR-7.4: Signal endpoints (`GET/POST /api/agent-os/signals`)
- FR-7.5: Experiment endpoints (`GET/POST /api/agent-os/experiments`)

## 4. Non-Goals (Out of Scope)

| Item | Why |
|------|-----|
| PostgreSQL persistence | v1.15 — JSON files are sufficient for single-instance |
| Auto-promote/rollback wiring | v1.15 — human reviews signals first |
| Statistical significance testing | v1.15 — POC uses threshold-only |
| Multi-instance tenant federation | v2.0 — single-instance only |
| Web UI for Agent OS | v2.0 — API-only for now |
| Cross-tenant queries | Explicitly forbidden — hard isolation |
