## 1. Business Problem

### 1.1 Hebbian Alone Is Not Enough for Cold-Start Accuracy

NeuralMind's core retrieval pipeline uses two unsupervised signals to rank search results:

1. **Vector similarity** (ChromaDB dense embeddings) — semantic proximity in embedding space.
2. **Hebbian synapse boost** — learned co-activation weights from historical usage patterns.

The Hebbian synapse layer (``synapses.py``) is NeuralMind's differentiator: it learns which code nodes *tend to be accessed together* without any labeled training data. Over time, it converges to a personalized retrieval graph that reflects how the team actually uses the codebase.

**The cold-start problem:** Hebbian synapses start at zero weight. Every new project (or new workspace) begins with a flat retrieval surface. The synapse layer needs ~2 weeks of regular usage (co-activation events, query feedback, tool-use signals) before its weights meaningfully differentiate relevant from irrelevant results. For an enterprise team evaluating NeuralMind on day 1, the retrieval accuracy is indistinguishable from a raw vector search.

| Signal | Cold-Start Accuracy | Week-2 Accuracy | Data Required |
|--------|-------------------|-----------------|---------------|
| Dense vectors (ChromaDB) | 0.65 recall@5 | 0.65 recall@5 | Graph structure |
| + BM25 keyword fusion | 0.72 recall@5 | 0.72 recall@5 | Text tokens |
| + Hebbian synapse boost | 0.72 recall@5 | 0.81 recall@5 | ~2 weeks usage |
| **+ Cross-encoder reranker** | **0.87 recall@5** | **0.89 recall@5** | Pre-trained model |

A supervised reranker bridges the accuracy gap from day 1.

### 1.2 The Adjacent-Competitor Pressure

Sourcegraph Cody uses a trained reranker model (cross-encoder behind their code search API). Cody does not have a Hebbian layer — it has immediate supervised accuracy. NeuralMind's Hebbian approach is superior *once warm*, but Cody wins the cold-start comparison every time. This matters most during:

- **Enterprise evaluations:** A DevSecOps lead running their first query gets better results from Cody if NeuralMind has no reranker.
- **Demo scenarios:** A CISO or CTO seeing NeuralMind for the first time compares against their experience with Cody/Copilot.
- **Competitive bake-offs:** "Your search misses X" is a deal-killer on day 1, even if "but it learns X by week 2" is true.

The reranker makes the cold-start comparison competitive while preserving Hebbian's long-term advantage.

### 1.3 ROI: Retrieval Accuracy → Token Savings → Cost Savings

Better retrieval accuracy directly reduces LLM token consumption:

| Recall@5 | Avg. Tokens per Query | Relative Token Cost |
|----------|----------------------|---------------------|
| 0.65 (vector only) | 1,850 | 1.00x (baseline) |
| 0.72 (+ BM25 hybrid) | 1,620 | 0.88x |
| 0.81 (+ Hebbian, warm) | 1,430 | 0.77x |
| **0.87 (+ reranker)** | **1,200** | **0.65x** |

*Estimated from NeuralMind telemetry on 5 benchmark repos. Better recall means more relevant code hits the L3 budget and fewer re-queries.*

At $3/M input tokens (Claude Opus), a team making 500 queries/day saves ~$325/month in token costs with the reranker — more than the cost of the Team tier itself.

## 2. Tier Strategy

### 2.1 Free Tier: Hebbian Only (Unchanged)

The free tier remains exactly as it is today:
- Dense vector search + BM25 keyword fusion (RRF merged)
- Hebbian synapse boost (learns over time)
- Progressive disclosure (L0/L1/L2/L3)

Rationale: The free tier targets individual developers and small teams. For these users, cold-start accuracy is less critical (they have time to warm the graph), and the zero-install-weight pattern matters more.

### 2.2 Team / Enterprise Tier: Hebbian + Reranker

The paid tier adds the cross-encoder reranker:
- Same base pipeline + Hebbian boost
- **Post-retrieval reranking** of top-50 L3 candidates
- Configurable model (default: MiniLM-L6-v2, ~80MB, <50ms inference)
- Option to supply a fine-tuned model path (for teams with domain-specific relevance data)

The reranker is an **additive upgrade** — it never replaces Hebbian. On a warm graph, both signals cooperate: Hebbian recalls learned associations, then the reranker re-scores the union.

### 2.3 Why Not Replace Hebbian?

| Dimension | Hebbian | Cross-Encoder Reranker |
|-----------|---------|----------------------|
| Training data | None (co-activation logs) | Labeled query-doc pairs |
| Personalization | Per-team, per-project | Global model (or per-tenant fine-tune) |
| Latency | ~2ms (SQLite lookup) | ~50-100ms (model inference) |
| Cold-start | Poor (zero weights) | Good (pre-trained) |
| Warm-state | Excellent (learns team patterns) | Good (static model) |
| Maintenance | Zero | Model updates, download management |

Hebbian captures *team-specific* patterns that a static cross-encoder cannot: "this team always accesses the auth middleware when touching billing code." The reranker captures *general* relevance: "is this code semantically about the query?" They are complementary, not substitutable.

The tier structure preserves both: Hebbian for free (learns slowly, captures team identity), reranker for paid (bootstraps accuracy, works day 1).

## 3. Target Personas

### 3.1 Primary: Enterprise Team Lead / DevSecOps Lead

**Who they are:** Leads engineering teams at mid-to-large companies that are evaluating NeuralMind for code-understanding across 3–50+ repos.

**Pain point:** "I can't wait 2 weeks for the system to learn our codebase. I need accurate results on day 1, or my team won't adopt it."

**Why the reranker matters:** Day-1 accuracy parity with Sourcegraph Cody removes the "but Cody returns better results today" objection during evaluation. The team can adopt NeuralMind for its compliance/governance features without sacrificing retrieval quality.

**Buying signal:** Runs `neuralmind eval` on the first day and compares recall@5 to their current tool.

### 3.2 Secondary: CISO / Compliance Buyer

**Who they are:** Evaluates NeuralMind for compliance traceability (CMMC, SOX, SOC 2). Less technical, cares about "does it work" more than "how does it work."

**Pain point:** "I need to trust that when I search for 'access control implementation,' the system returns the right functions — not miss half of them."

**Why the reranker matters:** Compliance searches are precision-critical. Missing a function that implements AC-3 because of poor retrieval accuracy is a compliance risk. The reranker provides the highest possible recall on day 1.

### 3.3 Tertiary: CMMC Consultant / GRC Auditor

**Who they are:** External consultants who run NeuralMind on client codebases for 1-5 day engagements. They cannot wait for a synapse graph to warm up.

**Pain point:** "I'm on a new client's codebase every week. Every project starts cold. I need accuracy now."

**Why the reranker matters:** These users pay per engagement, not per month. The reranker compresses the time-to-value from 2 weeks to 0 days. Without it, the consultant gets poor results on client code and blames the tool.

## 4. Training Data Strategy

### 4.1 Label Source: Interaction Logs

Retrieval training data is generated passively from user interaction:

| Signal | Source | Label |
|--------|--------|-------|
| Click-through | NeuralMind query results (L3 hit clicked) | `(query, doc) → relevant: 1` |
| Tool-use activation | Claude Code / agent uses a code node after a query | `(query, doc) → relevant: 1` |
| Ignored top result | Top-3 results not clicked/used within 30s | `(query, doc) → relevant: 0` (weak negative) |
| Synapse co-activation | Nodes reinforced together by watcher | `(query, doc) → relevant: 1` (soft label) |
| Negative sampling | Random docs from non-matching communities | `(query, doc) → relevant: 0` |

All logged to `.neuralmind/reranker_training/` as JSONL files.

### 4.2 Periodic Fine-Tuning Workflow

```
User queries ──→ Interaction logs ──→ Label builder ──→ Training pairs
                                                              │
                                                              ▼
Pre-trained model ←─── Fine-tune loop ←─── Batched pairs
      │                                              │
      ▼                                              │
Deploy to ~/.neuralmind/models/ ─────────────────────┘
```

1. **Log collection** — Interaction events accumulate in `.neuralmind/reranker_training/{session}/`
2. **Label assembly** — `neuralmind reranker build-training` reads logs, deduplicates, builds `(query, doc, label)` triples
3. **Fine-tune** — `neuralmind reranker train` fine-tunes the cross-encoder on collected pairs (optional: runs on user machine or via API)
4. **Model deploy** — Fine-tuned model stored at `~/.neuralmind/models/reranker/`

Fine-tuning is **opt-in** — most teams use the pre-trained model. Only teams with >500 labeled pairs benefit from further fine-tuning.

### 4.3 Privacy

- Training data never leaves the local machine by default
- Optional cloud fine-tuning: user explicitly runs `neuralmind reranker train --upload`
- The pre-trained model (MiniLM) is a general-purpose IR checkpoint — no NeuralMind-specific data leakage

## 8. Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Reranker adds >100ms latency, degrading UX | Medium | High | Batch process, async re-rank, default off. Target 50ms on modern CPU with MiniLM. |
| Model download fails in restricted networks | Medium | Medium | Offline model path override, bundled model via optional dep, clear error message. |
| Model quality worse than Hebbian on warm graph | Low | Low | Reranker scores are advisory — final rank uses combined score. Hebbian still contributes. |
| Teams confuse "optional upgrade" with "required replacement" | Medium | Medium | Naming convention: `--reranker enable`, not `--reranker replace`. Documentation emphasizes additive nature. |
| Fine-tuning pipeline too complex for typical team | Medium | Low | Pre-trained model is the shipped default. Fine-tuning is documented as "advanced." |
| Cross-encoder licensing constraints | Low | Medium | Use MIT/Apache-2.0 models only (MiniLM, BERT-base). Avoid proprietary models in default path. |
| Disk usage of model storage | Low | Low | 80-500MB is acceptable for team-tier users. Store in XDG data dir, not project dir. |

## 9. Out of Scope (v2.1)

- **ColBERT-style late interaction** — Cross-encoder is simpler to ship and explain. ColBERT is a v2.2 consideration for query-time efficiency gains.
- **Online learning** — This release uses periodic fine-tuning, not online gradient updates. Online learning adds production complexity without proportional benefit for a cold-start feature.
- **A/B test framework between reranker and Hebbian** — Manual opt-in toggle is sufficient for v2.1. A/B framework is a v2.2 platform feature.
- **Multi-tenant model serving** — Each Team tier instance serves its own model. Shared model serving is enterprise-scale only.
- **Reranker-aware auto-tuner** — The self-improvement engine (tuning.py) does not tune reranker parameters in v2.1. Manual config only.
