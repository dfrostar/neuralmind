### Post text

An AI coding agent works from a partial view of your codebase. The code it writes can be correct and still not fit: it skips a check the neighbouring code makes, edits a file a past decision covers, or renames something without updating every caller.

None of that fails a test on the day. It is technical debt someone pays for later.

NeuralMind gives the agent your project's structure and history, and checks its changes against them before they land:

• Pattern drift before commit: `neuralmind drift` groups each changed function with its siblings and flags the one that leaves out what the others do, like the tenth handler that forgot the auth check the other nine make.
• Decisions that go stale: record why the code is the way it is. When a commit changes a file the decision covers, the decision is marked STALE and the agent is warned before it edits.
• Blast radius: `neuralmind impact` lists every caller, importer and subclass of a symbol, so a rename reaches all of them.
• Co-change review: `neuralmind review` lists files usually edited together with the ones in your diff that the diff leaves out.
• Context that says when it is out of date, instead of answering from a stale index.

New in v4.22.0: `neuralmind doctor` now says whether anything is actually calling NeuralMind, and gives the command for each missing piece.

What we measure, and what we don't: on our public benchmark NeuralMind finds the file a fix changed on 40 of 40 queries, against 32 of 40 for keyword ripgrep. We have not shown that agents finish tasks faster. Our pilot found no difference, and the page says so.

Every guard, what each recent release added, and the evidence:
